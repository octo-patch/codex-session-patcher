## 1. 目标与范围

### 1.1 产品目标

Codex Session Patcher 是面向 Codex CLI、Claude Code 和 OpenCode 的本地会话修复与安全测试提示词管理工具，目标是：

1. 识别并替换会话中已经保存的拒绝回复。
2. 按用户选择清理独立或嵌入式推理内容。
3. 修改前创建可恢复备份，写入失败时保留原文件。
4. 为三个客户端提供彼此隔离的 CTF/授权安全测试提示词配置。
5. 通过 CLI 和本地 Web UI 提供一致的预览、修改、恢复和配置体验。
6. 可选调用用户配置的兼容 LLM 接口生成上下文相关替换文本。

### 1.2 非目标

- 不接管 Codex 的网络流量，不提供中间人代理。
- 不保证任何模型一定接受或完成特定请求。
- 不自动修改用户未由本工具管理的提示词、项目文件或技能目录。
- 不提供公网部署的多用户管理系统；Web 服务定位为单机本地工具。

### 1.3 目标用户

- 需要恢复被拒绝会话的 Codex CLI、Claude Code 或 OpenCode 用户。
- 在 CTF、授权渗透测试、逆向分析和安全研究场景中使用 AI 编码工具的人员。
- 需要可视化预览、批量清理、提示词编辑和备份恢复的用户。

## 2. 功能需求

### FR-001：多平台会话发现 [P0]

系统必须支持：

- Codex：发现 `~/.codex/sessions` 下的 JSONL 会话。
- Claude Code：发现 `~/.claude/projects` 下的 JSONL 会话并还原项目路径。
- OpenCode：发现 `~/.local/share/opencode/opencode.db` 中的会话。
- 按修改时间排序、选择最新或批量处理，并允许显式指定路径或格式。
- 目录、数据库或会话不存在时返回清楚的错误，不创建伪造数据。

### FR-002：拒绝内容检测 [P0]

系统必须采用两级检测：

1. 强拒绝短语允许全文匹配。
2. 弱拒绝词只检查消息开头，降低正常技术讨论的误报。
3. 用户自定义关键词按全文强匹配处理。
4. 检测支持中英文且不区分英文大小写。

### FR-003：会话预览与清理 [P0]

- Codex 和 Claude Code 必须按 JSONL 逐行解析，OpenCode 必须通过 SQLite 访问。
- 默认处理会话中全部已识别拒绝回复，而不是只处理最后一条。
- Codex 的 `response_item` 与冗余 `event_msg` 必须一致更新。
- 历史会话只有 `event_msg` 时仍应允许清理。
- 省略主语的拒绝句式，例如“不能继续做这件事”，必须识别。
- 桌面端 `event_msg/item_completed` 的 `AgentMessage` 必须与对应 `response_item` 一起替换。
- 如果存在 `thread_history` 投影，清理必须同步 `thread_items`；会话已完整投影时还要修正投影游标。
- 用户可以只处理选中记录，也可以关闭推理内容清理。
- 预览模式不得创建备份或写入任何目标文件。

### FR-004：替换内容 [P0]

- 默认使用明确、可继续对话的配合性回复。
- 用户可以在设置中修改默认回复。
- 可选 AI 改写必须结合附近对话上下文生成替换内容。
- AI 返回空文本、问号乱码或不可用内容时必须使用本地默认回复，不得写入损坏文本。

### FR-005：推理内容清理 [P0]

- Codex：删除独立 reasoning 类型记录，包括 `response_item` 和 `item_completed/Reasoning`。
- 已投影的 reasoning 记录必须从 `thread_items` 删除，关闭清理选项时不得改动。
- Claude Code：移除消息 `content` 中的 thinking 块，保留其他内容块。
- OpenCode：在事务中删除对应 reasoning part。
- 关闭清理选项时不得修改任何推理内容。

### FR-006：备份与恢复 [P0]

- 默认在首次实际修改前创建备份，`--no-backup` 只用于用户明确选择的 CLI 操作。
- JSONL 和配置文件备份必须保留原内容及权限，并使用不会覆盖既有备份的唯一名称。
- OpenCode 必须使用 SQLite 一致性备份接口，不得直接复制正在使用的数据库文件。
- JSONL 和配置写入必须通过同目录临时文件、刷新落盘和原子替换完成。
- Web UI 必须列出、对比并恢复属于目标会话的备份。

### FR-007：CTF 提示词配置 [P0]

#### Codex

- Profile 模式写入 `~/.codex/ctf.config.toml`，通过 `codex -p ctf` 使用。
- 全局模式修改 `~/.codex/config.toml` 中本工具标记的配置块。
- 支持 `developer_instructions` 追加模式和 `model_instructions_file` 替换模式，两者互斥。
- Profile 和全局配置都必须通过管理标记确认所有权；遇到没有管理标记的顶层提示词键时必须停止，不得覆盖或删除。
- 写入固定名称的提示词文件前必须确认管理标记；未知文件必须保留并报告冲突，已管理且内容变化的文件必须先备份再更新。
- Profile 与全局模式切换时，旧模式卸载失败必须立即停止，不得继续写入新模式。
- 卸载只能删除本工具记录并仍能确认所有权的提示词文件，不得遍历删除整个 prompts 目录。

#### Claude Code 与 OpenCode

- 使用专用工作空间隔离提示词，不修改普通项目。
- 默认提示词和自定义提示词落盘时都必须带有管理标记，保证安装、状态检查和卸载使用同一所有权依据。
- 删除前必须验证管理标记；无法验证时保留文件并报告冲突。

### FR-008：默认 Codex 提示词 [P1]

默认优化模板必须使用单文件三层结构，用户无需手动切换：

1. **通用执行规则**：直接回答、禁止空泛转向、缺少具体值时使用占位符并保留完整结构。
2. **CTF 工作流**：按侦察、验证、利用、取旗、复现和状态更新推进。
3. **专项规则**：根据 Web、Pwn、逆向、移动端、密码学、取证、云和容器等任务语义采用相应流程。

模板范围限于 CTF、授权安全测试、逆向和安全研究，不加入成人内容、化学或武器等无关规则。

### FR-009：提示词编辑 [P1]

- Web UI 保存的自定义提示词必须供后续 CLI 和 Web 安装流程共同读取。
- 已安装时保存提示词必须同步实际生效的配置或文件。
- 恢复默认模板必须同时更新实际文件与持久配置。
- 配置读取失败必须记录明确错误；不得因不存在的内部模块静默回退。

### FR-010：本地 Web UI [P1]

Web UI 必须提供会话列表、搜索、预览、清理、备份恢复、设置、提示词管理和实时日志。

安全边界：

- HTTP API 与 WebSocket 默认只接受回环客户端。
- CORS 只允许本机页面来源。
- 设置查询不得返回 AI Key 明文，只返回是否已经配置。
- 保存设置时，空密钥默认保留原密钥，避免页面加载后意外清空。

### FR-011：可选网络能力 [P1]

以下功能会发起网络请求，必须与本地会话清理核心区分：

- 用户启用 AI 改写后，请求用户配置的 OpenAI 兼容接口。
- 合作意向提交会发送用户主动填写的表单数据到 Muggle Leads 服务。
- Web 侧边广告会读取公开广告配置和图片。

AI 改写默认关闭。网络失败不得阻止本地会话浏览、默认替换或备份恢复。

## 3. 非功能需求

### 3.1 可靠性

| 编号 | 要求 |
|---|---|
| NFR-001 | 解析失败时不修改原文件 |
| NFR-002 | 目标写入采用原子替换，失败时清理临时文件 |
| NFR-003 | SQLite 更新使用事务，异常时回滚 |
| NFR-004 | 删除受管理文件前验证路径、类型和所有权 |
| NFR-005 | 同一秒内连续操作不得覆盖既有备份 |

### 3.2 安全与隐私

| 编号 | 要求 |
|---|---|
| NFR-006 | 本地配置目录和配置文件分别使用仅当前用户可访问的权限 |
| NFR-007 | Web 响应、日志和异常不得输出 API Key |
| NFR-008 | 会话内容只有在用户明确启用 AI 改写时才发送到指定接口 |
| NFR-009 | 不跟随受管理配置和提示词路径上的符号链接 |
| NFR-010 | 本地 Web 服务不接受远程客户端 |

### 3.3 兼容性与依赖

- CLI 会话清理核心只使用 Python 标准库。
- Web 功能使用 FastAPI、Uvicorn、Pydantic、HTTPX 和 WebSocket 依赖。
- 支持 macOS、Linux 和 Windows；平台差异必须进入自动化测试。
- Python 最低版本以 `pyproject.toml` 为准，CI 必须覆盖最低版本和当前主要版本。

### 3.4 可维护性与发布

| 编号 | 要求 |
|---|---|
| NFR-011 | CLI、Web、安装器共享配置和文件写入实现 |
| NFR-012 | 版本号只有一个权威来源 |
| NFR-013 | 每次发布构建 wheel 和源码包，并在全新环境安装验证 |
| NFR-014 | wheel 必须包含核心子包、Web 后端、默认提示词和前端构建产物 |
| NFR-015 | CI 必须运行单元测试、前端构建、离线提示词题库和发布包冒烟测试 |
| NFR-016 | 前端按需引入组件并拆分非当前页面，生产构建不得产生超过 500 kB 的 JavaScript 文件告警 |

## 4. 主要用户流程

### 4.1 修复会话

```text
发现会话 → 预览拒绝和推理记录 → 选择替换内容 → 创建备份
→ 原子写回 JSONL 或事务更新 SQLite → 查看结果或恢复备份
```

### 4.2 启用 Codex CTF Profile

```text
选择提示词与注入方式 → 预检现有配置 → 写入受管理提示词
→ 写入 ctf.config.toml → codex -p ctf 启动新会话
```

### 4.3 使用 AI 改写

```text
用户启用 AI 并配置接口 → 本地提取必要上下文 → 调用指定接口
→ 校验响应 → 使用 AI 结果或本地默认回复
```

## 5. 验收与验证

1. 现有源码测试全部通过。
2. 保存自定义提示词后执行安装，实际文件内容必须与保存内容一致。
3. 在 prompts 目录放置用户 Markdown，安装和卸载后该文件必须保持不变。
4. 模拟 JSONL 写入失败，原文件必须保持完整。
5. SQLite 在线备份可以打开并通过完整性检查。
6. 非回环 HTTP 和 WebSocket 请求被拒绝。
7. 设置接口返回值中不包含 AI Key 明文。
8. 构建 wheel，安装到全新环境后 `codex-patcher --help`、核心导入和 Web 导入成功。
9. 在无管理标记的 `ctf.config.toml` 中放置用户提示词键，安装和卸载都必须拒绝修改。
10. 预先放置无管理标记的同名提示词文件，安装必须保留原内容并返回冲突。
11. 使用自定义提示词完成 Claude Code、OpenCode 安装后，必须能够正常识别状态并完成卸载。
12. 模拟旧模式卸载失败，模式切换必须停止且不得创建新模式配置。
13. 默认提示词通过离线结构校验，包含三层结构和全部规定专项类型。
14. 前端生产构建不再产生 JavaScript 文件超过 500 kB 的告警。

## 6. 风险

| 风险 | 处理 |
|---|---|
| 客户端升级改变会话格式 | 格式策略隔离并增加真实样本测试 |
| 提示词过长或规则冲突 | 三层去重，使用离线题库和同模型对照测试 |
| 用户同时修改配置 | 写入前复核内容，无法确认所有权时停止 |
| AI 接口泄露会话隐私 | 默认关闭，界面明确提示发送范围，密钥不通过 GET 返回 |
| 发布包与源码行为不一致 | CI 从构建产物安装，不从源码目录执行冒烟测试 |
